本 PRD 的全部框架结论来自对真实小程序安装包的一手逆向拆解。核心结论：「LEXY莱克」不是自研代码，而是有赞微商城（Youzan WSC）SaaS 模板的实例化——莱克做的是「开通有赞店铺 + 后台配置 + 插件接入」，不是写代码。因此复刻的正确路径是 选对平台 + 配齐配置，而不是把 452 个页面重写一遍。

推荐路径：有赞微商城·连锁版（与现版同一框架，2–4 周上线）；若目标是快速承接 ADQ 广告与直播间流量，可先用微信小店（1–2 周）过渡。

最重要的一个结论

这个小程序的代码不是莱克写的，也不是外包写的——它是有赞微商城的标准小程序框架，莱克做的是「开通有赞店铺 + 后台配置（商品/栏目/装修/营销/会员/门店）+ 插件接入」。因此「复刻」的本质不是「把 452 个页面重写一遍」，而是选对平台、配齐配置。

为什么要拆这么多分包

async-core / async-main / async-minor / async-usecenter / async-feature-ext / async-retail / async-tee / async-video 与 goods-core / goods-main / goods-minor 这类命名是异步分包机制——把大模块拆成按需下载的子包，首屏只加载主包（461 文件），这是它能保持秒开的关键手段。

五、核心业务流程

以下五条链路覆盖了这套小程序的全部主业务，箭头即页面跳转顺序。

5.1 主购物链路（P0）

从首页到支付的标准电商闭环：

首页装修页 dashboard → 商品列表/搜索/分组 goods-list / shop/goods → 商品详情 goods/detail（含秒杀/拼团/砍价活动态）
→ 加入购物车 goods/cart → 确认订单 trade-buy/order/buy（地址、优惠券、积分、发票、自提）
→ 收银台 pay/unicashier（微信支付）→ 订单结果 trade/order/result → 订单列表/详情/退款 trade/order/list、refund/list

5.2 直播带货链路（P0 · 品牌部重点）

这是与 ADQ 投放、直播间转化直接挂钩的一条链：

视频号直播插件 live-player-plugin 进入直播间 → 直播间挂载商品（goods/detail 半屏）
→ 秒杀组件（export seckill.js）整点/限量抢购 → 下单支付同 5.1
→ 观看-下单归因数据回流有赞 statcenter

5.3 会员运营链路（P1）

复购与 LTV 的核心承载：

注册/登录 account/login（微信授权）→ 领取/购买会员卡 membercard、levelcenter/plus（付费会员）
→ 消费得积分 point → 积分商城兑换 pointstore → 领券用券 user/coupon、ump/coupon-pack
→ 储值充值 pre-card → 权益卡 benefit-card → 任务中心 user/task-center、签到打卡 ump/sign-in、new-punch

5.4 门店与连锁链路（P1）

莱克线下体系接入小程序的通道：

定位授权 scope.userLocation → 附近门店/门店列表 shop/chain-store、multi-store
→ 门店选择 shop-select → 到店自提地址 self-fetch-address ／ 门店核销 trade/cert/verify-ticket
→ 门店导购接待 retail/chat、guide

5.5 分销裂变链路（P2 · 可选开关）

原框架内置但莱克未必启用，需先确认再决定是否复刻：

分销员招募 salesman/salesman-center → 生成推广素材/朋友圈素材 zone/material、guide/pages/moments-material
→ 分享商品/直播间 order/share、wxvideo/cps → 成交佣金 salesman/report、rank、task-award → 提现

以上五条链路共同构成复刻的功能边界：P0 链路决定「能不能卖」，P1 链路决定「能不能留住人」，P2 链路属于增量选项。

七、非功能需求

这部分决定复刻出来的小程序「快不快、稳不稳、能不能过审」，往往比功能清单更容易被忽略。

类别要求
性能采用异步分包（async-* / goods-core 等）把首屏主包控制在 2MB 内；preloadRule 预下载门店与会员分包；onReachBottomDistance 400 提前触底加载
可用性统一错误页/停服页/空白页容器（packages/common），弱网降级到 H5（wxh5-downgrade 收银台 H5 降级链路）
兼容渲染层 renderer: webview（未启用 skyline），componentFramework: exparser，需兼容低版本基础库
安全合规requiredPrivateInfos + __usePrivacyCheck__：需在小程序后台配置隐私保护指引；位置权限需场景说明；支付走微信支付商户号
数据合规电商类目需营业执照 + ICP 备案 +（如涉食品/医疗器械）相应资质；用户信息收集需明示
可运营所有楼层/文案/活动均需后台可视化配置，禁止写死在前端

八、复刻实施路径（决策重点）

四条路径的成本与能力差异极大，这是本 PRD 最需要品牌部拍板的一章。

路径说明成本与原版一致度周期建议
A. 微信小店（官方）腾讯官方免费小店，原生打通视频号/ADQ低中（功能子集，无积分/储值/分销）1–2 周适合快速承接广告流量
B. 有赞 SaaS（原版同源）开通有赞微商城 + 连锁版，配置即得中（年费 + 交易费率）高（与现版同一框架）2–4 周（主要是配置与素材）最推荐，性价比最高
C. 自研小程序参照本 PRD 自建前后端高（研发 + 长期维护）取决于投入3–6 个月起仅在需深度定制/数据私有化时选
D. 混合微信小店承接广告 + 有赞承接会员运营中—并行可与 A/B 组合过渡

推荐结论

若目标是「复刻出一个能力对等的 LEXY莱克」，选 B（有赞微商城·连锁版）；若目标是「快速有一个能投 ADQ、能挂直播间的店」，选 A（微信小店），后续再平滑升级到 B。

分阶段交付计划（以路径 B 为例）

按 8 周节奏推进，每阶段都有可验收的交付物：

阶段周期交付
阶段一第 1–2 周有赞店铺开通、类目资质与支付商户号、品牌主题（#FF4444 主色）、自定义 tabBar
阶段二第 3–4 周首页装修（栏目按真机截图 1:1 复刻）、商品与分类录入、购物车/订单/支付联调
阶段三第 5–6 周视频号直播插件接入 + 秒杀配置、优惠券、客服
阶段四第 7–8 周会员/积分/门店连锁、隐私合规自查、上线
